# 0.6.0 验证记录

- 43项Node核心测试通过；20组Chromium流程测试通过；8组Java纯逻辑/执行器测试通过；Android35工具链编译及APK签名校验通过。
- 限额：单文件500MiB、单批1GiB、最多20个。界面简写为500MB/1GB。正文提取阈值50MiB，较大原件保留但不在导入时提取；计划表和照片仍使用独立限制。
- AttachmentTransfer测试实际流式传输100MiB生成数据，64KiB缓冲；SHA256标准abc向量、已知长度完整性、未知大小超额、已知501MiB提前拒绝、初始与中途可用空间不足均通过。复制与校验一次读取完成，异常由原调用清理目标文件。
- 大文件等待上限延长到30分钟，完成/失败后清理桥接超时定时器；浏览器回归验证完成导入不残留长等待定时器。
- PDF原页通过Android PdfRenderer.Page.render渲染，读取私有原PDF，不使用getTextContents来生成显示内容，不修改原件；Android35以上显式包含文本/高亮批注标志，旧系统使用原生展示模式。
- PageRasterSize测试：A4/横版/极端长页/巨大页面都满足4百万像素预算、尺寸上限、常规页面比例。PreviewQueue测试验证PDF查看不被正在导入的文件复制线程阻塞。
- original-reader浏览器测试：读取原文件路径、320页中跳转第201页、切换资料时过期页面响应不覆盖当前内容；渲染失败保留系统阅读器入口，不显示残缺提取摘要；共享PDF的多篇笔记完整保留40000字，混合目录的独立文本不丢；保留各分篇删除/分类/编辑、错题重做与OCR原图按钮；响应布局无横向页面溢出。
- large-import浏览器测试：100MiB原件元数据、额度提示、仅原件标志、应用内原页查看及主动系统阅读器打开路径正确。
- 两次独立审查覆盖限额流式复制及PDF查看；发现PDF笔记缺少管理动作、混合原图入口缺失，已补回并增加回归。
- 真实Android上的PdfRenderer页面输出、特殊字体/加密文档/复杂批注兼容、500MiB文件提供器复制与低存储情形仍未真机验证。浏览器图片由接口测试替身提供，不能作为真实PDF公式渲染的截图证据。
- Word/PPT等格式仍是文字预览，图片、公式及完整排版需打开原件；本版不宣称具有这些格式的原版式内嵌渲染。
