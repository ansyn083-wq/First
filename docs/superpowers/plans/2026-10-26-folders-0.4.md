# Folder library 0.4 implementation plan

Goal: import notes and multiple documents into folders, ordered access, saved current folder and a more readable viewer.
Architecture: extend local state with scoped folders, folderId/order and library preferences. One native multi-document picker with partial-failure results and pending-batch recovery. Keep originals; merged note text and folder continuous reading are optional and bounded without silent truncation. Existing ID/API and tasks remain.

- [x] Core tests: legacy migration, natural filename order, merge/split text preservation, backup round-trip folder membership/attachments/order.
- [x] Add folder logic module and core backup support; UI folder rail, create/rename/empty-delete, move/reorder, remembered selection, single/continuous reader with font controls and original links.
- [x] Native batch imports (20 files/100MiB batch,50MiB each), partial-error reporting, pending batch recovery; DOCX bounded text extraction with Java tests. TXT/MD use existing text extraction; PDF extraction stays Android15+. No embedded PDF/PPT renderer.
- [x] UI integration test: note batch import natural order, merged text, folder reopening, non-destructive failure, backup; existing full test suite.
- [x] Review, build versionCode4/version0.4.0 same package/signature, save APK and source.

Review focus: native result arriving after navigation retains chosen target; save failure does not acknowledge pending files; import failure preserves originals and existing notes; backup preserves folders but cannot carry binary attachments; no HTML from imported documents executes. Long combined notes split at 20000 characters and all source text retained; unavailable text stays an attachment with explicit message.
