# 研序 0.7.0 验证记录

日期：2026-10-27。Android versionCode 10，包名 cn.kaoyan.assistant，沿用此前签名。

## 行为与边界

- PDF沿用Android PdfRenderer原页阅读。DOC/DOCX/PPT/PPTX打开时仅查本地缓存；用户明确点击转换后才上传到设置中显示的独立HTTPS服务。
- 转换服务和令牌独立于AI配置。地址与令牌以一个加密配置保存；排队后配置变化会拒绝旧任务，避免上传到另一个地址。Office配置解密失败不会阻塞整个应用启动。
- 转换PDF经字节保存、同步及Android PDF解析验证后才替换缓存。失败保留源文件和已有缓存。清理转换缓存保留原件与手动关联PDF。
- 支持关联已导入PDF，无需服务器即可离线阅读。合并重复文件时保留/重映射关联，保存失败可回滚。
- 继续保留各板块导入隔离、去重、顺序整理和先前500MiB单文件/1GiB批次/20文件限制。

## 验证

- Node：45项核心测试通过。
- 浏览器首轮发现旧文件夹测试在保存回调前读取界面的时序问题；补充等待实际文件夹显示后重新运行。
- Chromium：21组浏览器交互测试通过，包含Office显式上传、缓存、失败保留、离线关联、配置界面与异步结果隔离。
- Java：9组测试通过，包含缓存命名/失效、清理保留原件与DOC MIME。
- Python：2组服务集成测试通过。实际使用本地LibreOffice转换DOCX、PPTX、DOC、PPT和RTF格式DOC；检查多页、表格文字、图片和简单公式。覆盖认证、超限、错误格式与临时文件清理。
- APK重新构建成功，核对打包资源与源码并验证v2/v3签名。
- 静态复查发现并修正排队转换的地址变化竞争，以及Office/PDF重复合并时的关联与回滚问题。

## 尚未覆盖

- 未使用Android平板真机；浏览器测试模拟原生桥，Java测试不等于Android HTTPS端到端测试。
- 本机LibreOffice为26.8开发版。交付Docker使用发行版LibreOffice；环境没有Docker，未验证镜像构建。没有用户服务器、域名或凭据，未进行远程部署。
- 自动转换需要自行部署附带服务，在App设置填写服务地址与独立令牌。已有PDF离线关联不需要此服务。
- 无法保证任意Office文档完全一致，特别是缺失字体、复杂公式和排版；PPT只转换静态页，不播放动画、视频或音频。原件始终保留。
- 普通学习备份不包含原件和转换缓存二进制；恢复备份后需要重新导入资料。
