# 研序 0.4.0

Folders now organize notes, mistakes and courseware. Existing records migrate to default folders. Each section remembers its selected folder. Imports create a named folder or use an existing folder; natural filename sorting handles numbered lessons. Users can reorder, move records, rename folders and delete empty custom folders.

Multiple-file native picker supports up to20 files,50MiB each,100MiB aggregate. Per-file errors are reported without discarding successes. Originals remain separate. TXT/MD and bounded DOCX text become notes; PDF text extraction requires Android15+, unsupported/scanned content stays an attachment. Optional merged notes split at20000 characters without truncation and retain original links. Partial PDF notices survive note creation. A pending-batch AtomicFile recovers accepted imports after interruption. A save failure does not acknowledge the journal and preserves access to prior data.

Reader: warm paper background, adjustable16–22px text, previous/next item, whole-folder combined reading, source attachments and note editing actions. Folder metadata, ordering and attachment references survive JSON backup; binary files are still excluded. Delayed saves cannot render a folder over a newly navigated page. Startup initialization moved after all scripts to ensure recovery functions exist when native load replies quickly.

Validation:28 Node tests pass. Eight desktop Chromium suites pass: existing UI, retrieval/stat races,0.2 features,OCR race,0.3 settings,folder import/reopen/merge/sort/escaping/partial failure/responsive UI,pending import failure,delayed folder persistence. Java UTF8 size/XLSX/DOCX tests pass. Fresh review found startup capacity lockout and delayed rendering race; both fixed with failing-then-passing regression tests. Minor legacy order, late reader-font update and partial extraction warning issues addressed. Tablet and phone screenshots inspected internally.

APK built with versionCode4/version0.4.0, same package/signing identity as earlier versions. Not tested on a physical Android device. System picker multi-selection, actual device DOCX/PDF/native import and third-party document viewer behavior require device testing. Source file representation preserves text and originals; layout, equations and images in DOCX are not converted into a rich document renderer. UTF8 TXT/MD decoding only. Multi-file import does not merge binary PDFs/PPTs into one binary document. Originals are available via system viewers.
